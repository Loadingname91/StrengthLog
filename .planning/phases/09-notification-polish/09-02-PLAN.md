<design_refinement>
## Refinements over 09-CONTEXT.md, found while working out the exact wiring

- **`FINISH_TAPPED` never dispatches `FINISH_WORKOUT` directly from the effect layer.** 08-CONTEXT.md's original sketch (referenced by 09-CONTEXT.md D-02) has the tap "route to the existing ConfirmSheet flow" — but *whether* a confirm sheet is even needed depends on `allSetsLogged`, a fact only `ActiveWorkout.jsx` computes. The effect layer stays a thin, workout-content-agnostic router (matching its existing character — it doesn't know about sets/exercises, only primitives) by setting a flag; `ActiveWorkout.jsx`'s own `finish()` (the exact function its own Finish button already calls) decides what happens next.
- **`allSetsLogged`, `finish()`, and `doFinish()` move to before `ActiveWorkout.jsx`'s `if (!aw) return null` guard.** The new finishRequested-consuming effect is a hook (`useEffect`), which — per the Rules of Hooks — cannot be declared after a conditional early return. Hoisting these three (with `allSetsLogged` null-guarded to `false` when `aw` is null) lets the new effect call the *exact same* `finish()` the Finish button uses, rather than duplicating its two-line decision inline. Everything after the guard that already referenced them is unaffected — they're still in scope, just declared earlier in the same function body.
- **App.jsx's Shell gains the navigation, not ActiveWorkout.jsx.** If the app is foregrounded on some other screen (Home, Settings) when Finish is tapped, `ActiveWorkout.jsx` isn't even mounted, so its own effect can't fire. `Shell` (already the home of `useAndroidBackButton()`, already has `useStore()`/`useNavigate()`/`useLocation()`) is the one place guaranteed mounted regardless of route — it only navigates, never dispatches; `ActiveWorkout.jsx` remains the sole reader/clearer of the flag once it mounts.
</design_refinement>

    Rewrite effect E's `apply()` from the two-way ternary to a three-way branch:
    ```js
    function apply(a) {
      if (a.workoutId !== stateRef.current.activeWorkout?.id) return
      if (a.type === 'REST_SKIP') dispatch({ type: 'REST_SKIP' })
      else if (a.type === 'REST_ADJUST') dispatch({ type: 'REST_ADJUST', payload: a.payload })
      else if (a.type === 'FINISH_TAPPED') dispatch({ type: 'SET_FINISH_REQUESTED', payload: true })
    }
    ```

    Add a resume listener alongside the existing mount-time drain and live-event subscription:
    ```js
    native.drainPendingActions(apply)
    const resumeSubPromise = CapacitorApp.addListener('resume', () => native.drainPendingActions(apply))
    const actionSubPromise = native.onWorkoutAction((a) => { apply(a); native.ackAction(a.id) })
    return () => {
      resumeSubPromise.then((sub) => sub.remove())
      actionSubPromise.then((sub) => sub.remove())
    }
    ```
    (Rename the existing `subPromise` to `actionSubPromise` for clarity now that there are two subscriptions.) Update the effect's doc comment to mention the resume path closes the "backgrounded but the WebView was frozen/suspended, not fully killed" gap that a mount-only drain misses.
