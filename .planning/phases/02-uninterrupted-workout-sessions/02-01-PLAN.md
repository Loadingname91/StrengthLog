<objective>
Add a persistent, tappable "workout in progress" floating bar with a live running clock, visible on every screen that has bottom navigation (Home, Routines, Stats hub, Settings) whenever a workout is active, and confirm/harden that leaving Active Workout never discards the in-progress session and that the elapsed clock stays wall-clock-accurate across backgrounding.

Purpose: `state.activeWorkout` already survives route changes structurally (it lives in the single global reducer state, not component-local state), and the bottom nav's "Log" tab already routes back into `/workout` when a session is active. What's missing is the persistent visual affordance the phase goal calls for — a bar visible from anywhere confirming the session is alive and showing elapsed time — plus a snappier clock refresh on app-foreground. This plan closes SESSION-01 through SESSION-04.
Output: new `src/components/SessionBar.jsx`; `src/App.jsx` mounts it; `src/screens/ActiveWorkout.jsx` gets a foreground-refresh listener for its own clock.
</objective>

## Phase Goal

**As a** FitLog user, **I want to** see and return to my in-progress workout from anywhere in the app, with an always-accurate running clock, **so that** I never lose track of an active session just because I checked my routines list or glanced at stats mid-workout.

**This plan's slice of the story:** the persistent session bar and the wall-clock-accuracy guarantee. (This phase has no second plan for session continuity — target-weight/ghost-fallback is a separate, unrelated requirement cluster covered by 02-02-PLAN.md.)
