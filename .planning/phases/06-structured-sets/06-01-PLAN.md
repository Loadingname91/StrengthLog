<objective>
Replace a block's flat `sets: N` count + single `rest` value with an explicit, ordered `sequence` of set/round/rest steps — authored in Routine Builder, backfilled transparently for existing routines — and extend the existing superset merge/ungroup to build/split that sequence correctly.

Purpose: this is the data-model half of Phase 6. It makes rest a first-class, editable part of the routine (REST-01/02/03), guarantees old routines keep working with zero data loss (REST-04), and gives supersets the round-aware structure Active Workout's runtime (06-02) needs to actually alternate exercises (SUPER-01).
Output: a new `src/lib/blocks.js`, an updated `blockTarget()`, and `RoutineBuilder.jsx`'s block editor + merge/ungroup logic. Active Workout is untouched — 06-02 consumes `sequence` next.
</objective>

## Phase Goal

**As a** person building a routine, **I want to** see and shape rest as part of my set plan, and merge exercises into a superset that actually alternates, **so that** the routine I build matches how I actually intend to train it.

**This plan's slice of the story:** the data model and Routine Builder's authoring UI. Active Workout's runtime is 06-02.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Persisted routine data → runtime read | Every existing routine in a user's `localStorage` lacks `sequence`. `backfillSequence` must never throw or silently drop data for any previously-valid `block.sets`/`block.rest` shape — a defect here would look like "my routine's sets disappeared" on first load after this update. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|--------------|------------------|
| T-06-01 | Tampering (silent data change) | `backfillSequence` | high | mitigate | Backfill is a pure, non-destructive read-time transform — it never writes back to `localStorage` on its own (no call site in this plan persists a backfilled block unless the user actively edits and saves it via `BlockEditSheet`, which is the same save path that already exists today). Mitigated by `blocks.test.js` asserting exact step count/order for representative old-shape blocks, and by REST-04's explicit "no behavior change until edited" success criterion. |
| T-06-02 | Denial of service (can't remove last set) | Sequence editor remove control | low | mitigate | Removing the last set/round is disabled in the UI (button hidden), mirroring the existing `REMOVE_SET` reducer guard's UX precedent — verified in `blocks.test.js`/`RoutineBuilder.test.jsx`. |

</threat_model>
