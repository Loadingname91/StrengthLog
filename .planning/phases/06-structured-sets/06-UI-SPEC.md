# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by design pass following `06-CONTEXT.md`.

## Phase Scope Note

`06-CONTEXT.md` (D-01 through D-14) locks the data model and most behavior; it explicitly leaves two things as open design surface: **the Routine Builder sequence editor** (replacing the "Sets" number input) and **the merged-superset Active Workout card** (how two exercises read as one interleaved flow). This document resolves both precisely.

**Key resolution, worth stating up front:** the merged-superset card does **not** need a separate "jump between exercises" mechanism. Phase 5 (Fast Set Entry, independent but shipping around the same time) already builds a confirm-to-advance focus chain between fields. SUPER-02's "auto-advance to the next exercise in the round" is the *same* chain, just crossing from exercise A's row into exercise B's row within a round instead of only advancing within one exercise's own sets. This means the merged card can show **every round as a flat, scrollable list** (matching today's single-exercise set list shape) — no tabs, no "current exercise" switching UI at all. Both exercises' current-round rows are already adjacent in that list.

No new screens. No new color tokens beyond one addition (see Color). Copy additions are small (round/rest labels).

## Interaction & Animation Contract

### A. Routine Builder — Sequence Editor (replaces the "Sets" number input in `BlockEditSheet`)

**Layout:** where today's grid has a "Sets" numeric input (top-left of the 2x2 grid in `BlockEditSheet`), it's replaced by a `Field label="Sequence"` spanning the full width, containing an ordered vertical list:

- **Set/round row:** a compact row, `flex items-center justify-between`, height ~32px: left side shows the ordinal label ("Set 1", "Set 2", ... for `type: 'single'`; "Round 1", "Round 2", ... for `type: 'superset'`) in the existing bold-13px set-number style; right side shows a remove `×` (`var(--danger)`, `text-lg`, matching `RoutineBuilder.jsx`'s existing menu "Remove" styling) — hidden/disabled when this is the sequence's only remaining set/round (mirrors the existing "can't remove the last set" guard, D-08).
- **Rest row:** same row height, dashed border (`border-dashed`, `var(--border)`), `var(--surface-alt)` background, rounded `rounded-lg`: a small clock glyph (reuse `ClockIcon` from `src/components/Icons.jsx`, already used by `SessionBar`) + a numeric `<input type="number">` (`w-20 text-sm text-right`, matching the exact classes of the existing "Default rest (sec)" input in `Settings.jsx` line 52) + "sec" label, right-aligned `×` remove control.
- **No-rest gap:** where two set/round rows are adjacent with no rest step between them, render a thin `+ Add rest` ghost link (`text-xs`, `var(--accent-dark)`, no border/background — a tap target, not a visible row) in the gap. Tapping it inserts a `{type:'rest', seconds: state.settings.restDefault}` step there.
- **"+ Add Set" button** (renamed from today's implicit behavior, same visual treatment as the existing dashed "+ Add Exercise" button elsewhere in this screen): appends one new set/round step AND a rest step after it (defaulting to `state.settings.restDefault`, per REST-03) — the rest step then appears as a normal removable row, per D-07.

**Spacing between rows:** `gap-1.5` (6px) between each row/gap in the list — tighter than the sheet's own field spacing (`mt-1` elsewhere in `BlockEditSheet`), since this is a single compound field, not a series of independent fields.

### B. Active Workout — Rest row inline in the set list (REST-05)

For a `type: 'single'` exercise's set list, a rest step from `sequence` renders as its own row between the relevant set rows, using the **same visual grammar as the Routine Builder's rest row** (dashed border, `var(--surface-alt)`, clock glyph) but read-only (no seconds input — just "Rest — 90s" text, `text-xs`, `var(--muted)`), height-matched to a set row (`py-2`, matching `SetRow`'s existing `border-t py-2`).

**Three visual states**, driven by position relative to the current step pointer:
| State | Condition | Treatment |
|-------|-----------|-----------|
| Upcoming | Rest step is after the current step | `opacity-60`, static (no countdown) |
| Active | Rest step is the current step (`aw.restUntil` is set and points at this step) | Full opacity; a small live countdown appended to the label ("Rest — 0:42 left") — this is *in addition to* the existing sticky bottom overlay's countdown, not a replacement (D-10: complementary) |
| Passed | Rest step is before the current step | `opacity-40`, a small checkmark glyph replaces the clock glyph |

This exactly mirrors how `SetRow` already dims nothing but marks `done` sets via background color (`set.done ? 'var(--accent-light)' : 'var(--surface)'`) — the rest row's opacity-based states are a new but consistent pattern for the same "where am I in this list" purpose.

### C. Active Workout — Merged superset card (SUPER-02, SUPER-03)

**Card header:** both exercise names on one line, joined by a "+" glyph, same `.font-serif text-[19px] font-semibold` treatment as today's single-exercise header — e.g. "Bench Press + Barbell Row". If this exceeds the card's width, apply `truncate` (existing app-wide pattern, e.g. `SessionBar`) rather than wrapping to a second line, keeping the card's header height consistent with single-exercise cards.

**Exercise-chip strip** (the horizontal scrollable strip above the card, `aw.exercises.map(...)` today): a merged superset renders as **one chip**, not two — label is the same "Name + Name" truncated text as the card header, at the chip strip's existing `text-xs font-semibold` size. Tapping it (via `GOTO_EXERCISE`, retargeted to the merged unit's index) behaves exactly as today: scrolls/sets that unit active.

**Set list body:** rounds render as grouped blocks, each block being one `<div className="rounded-xl p-2.5" style={{background: 'var(--surface-alt)'}}>` containing:
1. The round ordinal label ("Round 1"), `text-[13px] font-bold`, `var(--muted)`, same position as today's set-number column.
2. One compact row per exercise in the pair (reusing Phase 5's enlarged `SetRow`, one instance per exercise), each prefixed with a small exercise-name label (`text-[11.5px] font-semibold`, `var(--muted)`) sitting where a single-exercise row's "Last" ghost-value column sits — since a merged row can't rely on a card-level "this is exercise X" context the way a single-exercise card can.
3. If the round completed both exercises' sets, the whole round-group's background can optionally lighten toward `var(--accent-light)` (same signal `SetRow` already gives a `done` set) — Claude's discretion at build time whether this reads clearly without becoming visually noisy; the underlying done-state is already tracked per set regardless of this treatment.

Rounds render in the same flat, scrollable list a single exercise's sets do today — **no per-exercise tabs, no separate "now showing: Bench Press" indicator.** The exercise-chip strip's merged chip is a navigation/identity aid (matches the pattern already established for jumping between different blocks), not a mode switch within the merged unit itself.

**Auto-advance is a focus-chain extension, not new navigation UI:** confirming the second exercise's Reps in a round (per Phase 5's chain) moves focus to the *first* exercise's Weight of the next round (or, if a rest step follows, blurs — the sticky rest overlay takes over, same as today's single-exercise behavior). No new interaction pattern is introduced here beyond what Phase 5 already builds; Phase 6's runtime plan (06-02) wires the chain across the merged unit's flattened step list instead of one exercise's flat `sets` array.

### D. Rest timer's existing sticky overlay — unchanged

The bottom sticky countdown overlay (`restVisible` block, `ActiveWorkout.jsx` ~line 206) is **not redesigned** by this phase — its ring/±15s/Skip controls stay pixel-identical. It remains the live, actionable rest UI; the new inline rest rows (both Routine Builder's authored view and Active Workout's set-list view) are the "what's the plan" view, per D-10.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Sequence editor: set row (single) | "Set {n}" (unchanged from today's set-number label) |
| Sequence editor: set row (superset) | "Round {n}" (new) |
