<objective>
Consume Phase 6's `sequence` data model in Active Workout: a superset becomes one merged runtime unit whose sets interleave both exercises' rounds, rest renders as an explicit row in the set list, and completing a set advances into the next one — whether that's the same exercise's next set or the paired exercise's set — using the same focus-chain Phase 5 already built, not a new navigation mechanism.

Purpose: this is where REST-05, SUPER-02, and SUPER-03 actually become true for the person logging a workout — 06-01 only changed how a routine is authored.
Output: `buildActiveWorkoutFromRoutine`, `TOGGLE_SET_DONE`, `ADD_SET`/`REMOVE_SET`, and `FINISH_WORKOUT` in `reducer.js`; the set-list rendering and rest display in `ActiveWorkout.jsx`. No change to `session.entries[].sets`'s persisted shape.
</objective>

**This plan's slice of the story:** Active Workout's runtime. Depends on 06-01's `sequence` field existing on every block.

## Refinement of 06-CONTEXT.md's D-11/D-12 (documented explicitly, per this project's convention of recording such calls — see Phase 3's self-review catch)

`06-CONTEXT.md` sketched a nested step-type union (`{type:'set'}`/`{type:'rest'}` per exercise, with a step-index pointer). Working through the exact reducer/render changes at plan time surfaced a simpler, equivalent design that satisfies the same success criteria with a much smaller diff against the existing reducer:

- Every unit (single or superset) keeps a **flat `sets` array** — the same shape `TOGGLE_SET_DONE`/`SET_SET_FIELD`/`ADD_SET`/`REMOVE_SET` already index into today. No step-index pointer is added to state.
- Each set gains an `exerciseIndex` (always `0` for a single-exercise unit; `0..N-1` cycling for a superset's N-exercise pair) identifying which exercise in `exerciseIds` it belongs to.
- Each unit gains a parallel `restAfter` array (same length as `sets`): `restAfter[i]` is the rest duration to start after set `i` is completed, or `null`/`undefined` if none. This single array replaces `ex.rest` (a uniform value) AND today's `isLastInPair`/`pairIndex`/`pairSize` fields (a superset-specific special case) — `isLastInPair(aw, exerciseIndex)` becomes simply `ex.restAfter[setIndex] != null`, correct for both single and superset units without a branch.
- **No new focus/navigation state is needed for SUPER-02.** Phase 5's ref-chaining already advances from `sets[setIndex]`'s Reps field to `sets[setIndex + 1]`'s Weight field. For a merged superset unit, `sets[setIndex + 1]` is simply the *other* exercise's set in the same round (or the next round's first exercise) — the chain crosses exercises automatically because the array is flat and ordered correctly by `expandUnit` (below). This is why 06-02 has no "step pointer" reducer state at all.

This keeps the diff against `reducer.js` small (a handful of lines in 4 existing cases, one new helper) instead of introducing a parallel state model.
</design_refinement>
