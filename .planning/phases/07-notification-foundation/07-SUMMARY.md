# Phase 7: Notification Foundation Summary

Implements NOTIF-01 through NOTIF-08 — every notification trigger buildable without native Android code, plus the settings/permission UX and effect-layer architecture that Phase 8's foreground service will plug into.

## What Was Built

1. **The effect layer** (`src/state/useWorkoutNotifications.js`), mounted in `StoreContext.jsx` right after the existing `saveState` effect. Four watchers — lifecycle (start/stop), content (rest/exercise/progress), PR celebration, and reminders — each depending only on primitives derived from `activeWorkout`, never the object itself. This is the single most important architectural decision in the phase: `SET_SET_FIELD` (every weight/reps keystroke) replaces `activeWorkout` with a brand-new object on every dispatch, and a naive `[activeWorkout]` dependency would flood the native bridge on every character typed. A dedicated test dispatches ten keystrokes and asserts zero `updateWorkout` calls.

2. **`src/lib/reminderPlan.js`** — a pure `buildReminderPlan(state, now)` that tracks the exact "next up" routine `Home.jsx` already shows, reusing `dueInfo()`/`weekdayName()` from `src/lib/schedule.js` rather than inventing a parallel per-routine weekly schedule. Fully unit-tested (5 tests covering sequence mode, weekday mode, overdue, and "already past today's reminder time" edge cases).

3. **`src/lib/nativeNotifications.js`** — the platform-guarded client. Started as a pure no-op stub (so the effect layer could be built and tested before any plugin existed), then wired to `@capacitor/local-notifications` for reminders, PR celebrations, and a provisional rest-done alert. Every scheduled notification sets `isExactNotification: false`, avoiding the plugin's default behavior of opening Android's exact-alarm settings screen on first use.

4. **Settings gains a Notifications card** (native builds only — hidden via `Capacitor.isNativePlatform()` so the web/Pages build never shows dead toggles): rest alerts, ongoing notification, PR celebrations, and reminders (with a time picker), reusing the existing `Row` + checkbox pattern from "Show RIR chips."

5. **Generic settings backfill**: `buildInitialState()` now merges `initialSettings()` defaults under whatever the user has persisted, fixing a real pre-existing gap (no backfill existed at all) for every future settings key, not just this phase's five new ones.

6. **Three real rest-timer bugs fixed** while building the data layer the notifications depend on: `REST_ADJUST` was unclamped (could push `restUntil` into the past) and didn't update `restTotalSec` (letting the progress ring exceed 100%); the ding-played guard was a plain boolean that couldn't fire twice for a new deadline after a "+15s" tap; and `RestRow`'s active-state check compared rest *duration* instead of the actual set index, so two sets sharing a rest length both lit up as active simultaneously.

7. **Notification icon and branding**: `android/app/src/main/res/drawable/ic_stat_workout.xml` (an alpha-only white barbell — the app's real launcher icon is full-color and would render as a white blob), and `capacitor.config.json`'s `LocalNotifications.{smallIcon,iconColor}` config using the app's own accent color.

## Verification

115 tests passing (up from 84 at the end of v1.1), lint clean (no new warnings), production build clean, and a real-browser Playwright run (create routine → start workout → log/finish a set → visit Settings) confirmed zero console/page errors with the new `@capacitor/local-notifications` dependency in place. `npx cap sync android` ran successfully in this environment (no Android SDK required for that step) and regenerated the two tracked gradle files correctly.

## What's Deliberately Not Here

The ongoing Spotify-style notification and wake-lock-exact rest timing need a custom Android foreground service — real Java/Kotlin that this session's environment (Java + Gradle, no Android SDK) cannot compile or verify. That's Phase 8, fully designed in `../08-ongoing-notification/08-CONTEXT.md`, picked up on a machine with a real Android toolchain.
